# Формат интервью при предложении вакансии — СТРОГО

Когда предлагаю вакансию сэру, использую следующий формат. **Нарушение = грубая ошибка.**

## Обязательные шаги

1. Показывать 1-2 вакансии за раз
2. Полные данные: должность, компания, график, опыт (требуется/нет), адрес/локация, зарплата
3. ПОЛНОЕ описание — получать через `hh_vacancy.py`, показывать весь `description_text` целиком, не пересказывать кратко
4. Ссылка на вакансию (всегда показывать сразу, не скрывать)
5. Запрос решения: «Ваше решение, сэр?»

## Шаблон

```
━━━ ПРЕДЛОЖЕНИЕ ВАКАНСИИ ━━━

🏢 Должность: [Название]
📍 Компания: [Название]
💰 Зарплата: [Сумма]
🏢 Адрес: [Адрес / станция метро]
📅 График: [полный день / сменный / гибкий / удалённо]
💼 Опыт: [требуется / не требуется / Х лет]
📋 Обязанности:
[Обязанности из описания]

✅ Требования к кандидату:
[Требования из описания]

📄 ПОЛНОЕ ОПИСАНИЕ (строго):
[Весь description_text из hh_vacancy.py ПОЛНОСТЬЮ]
[НЕ СОКРАЩАТЬ! НЕ ПЕРЕСКАЗЫВАТЬ! НЕ РЕДАКТИРОВАТЬ!]
[Если описание длинное — показывать целиком, не обрезая]

🔗 Ссылка: [URL — всегда показывать сразу]
━━━
Ваше решение, сэр?
```

## ⚠️ КРИТИЧЕСКОЕ ПРАВИЛО

- Описание должно быть ПОЛНЫМ — весь текст из `description_text` hh_vacancy.py
- ЗАПРЕЩЕНО: сокращать, пересказывать своими словами, редактировать, делать краткую выдержку
- Если описание 5000 символов — показать все 5000
- Единственное исключение: если описание содержит HTML-теги — можно показать чистый текст
- При показе вакансии копировать весь текст целиком, без сокращений и пересказа
- Нарушение этого правила — ГРУБАЯ ОШИБКА, сэр будет недоволен

## Правила презентации

- Ссылку на вакансию показывать сразу, не скрывать — сэр сам решает переходить или нет
- При наличии конкретного адреса у вакансии — проверять расстояние от Горского 39 через OSRM API + Nominatim (см. `distance-osrm.md`). Если адреса нет — расстояние не проверять.
