# Учёт вакансий (history.json)

Файл: `scripts/history.json` (рядом со SKILL.md)

## Формат записи

```json
{
  "jobs": [
    {
      "url": "https://hh.ru/vacancy/123456",
      "title": "Python разработчик",
      "company": "ООО Пример",
      "salary": "150 000 - 200 000 ₽",
      "offered_at": "2026-07-03T09:00:00",
      "status": "pending",
      "user_response": null,
      "notes": null
    }
  ]
}
```

## Статусы

| Статус | Значение |
|--------|----------|
| `pending` | предложено, ожидается ответ |
| `interested` | сэр заинтересован |
| `rejected` | отклонено (записывать с причиной в notes) |
| `applied` | сэр откликнулся |
| `saved` | отложено на потом |

## Обязательства

- **Перед предложением вакансии** проверять все URL в history.json — не предлагать повторно.
  Проверять по URL. Если URL нет — проверять по названию вакансии + компания.
  Если вакансия уже в истории со статусом applied, rejected или saved — **НЕ ПРЕДЛАГАТЬ**.
  Нарушение этого правила — грубая ошибка.
- **После ответа сэра** немедленно обновлять запись.
- Если сэр откликнулся — менять статус на `applied`.
- Вакансии на потом сохранять в history со статусом `saved`.
- **Перед автооткликом** (`main.py apply`) проверять history.json — не откликался ли сэр уже на эту вакансию.
- При запросе поиска сначала брать saved-вакансии из history.json, только если их нет — запускать новый поиск.
